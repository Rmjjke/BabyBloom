# Weight Gain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Превратить экран Growth из «где мой ребёнок на кривой» в «достаточно ли он прибавляет». Три новых ответа: восстановление веса рождения в первые две недели, скорость набора в г/нед против нормы, устойчивый снос по центильному коридору. Плюс поддержка недоношенных через корректированный возраст и проактивные напоминания.

**Architecture:** Чистый SwiftUI + SwiftData без view-моделей (сохраняем подход проекта). Вся математика выносится в новый неUI-слой `BabyBloom/Core/Growth/` с чистыми функциями без зависимости от SwiftData — так она тестируема и переиспользуема виджетом. `WHOPercentile` из `GrowthEntry.swift` переезжает туда же и получает настоящие LMS вместо нормального приближения.

**Tech Stack:** Swift 6, SwiftUI, SwiftData (+CloudKit), StoreKit 2, UserNotifications, XcodeGen, XCTest.

## Global Constraints

- iOS 17.0+, Swift 6.0 (из project.yml — не менять).
- Проект генерируется XcodeGen: после изменения project.yml всегда `xcodegen generate` И проверка, что ключ реально подхватился (XcodeGen молча игнорирует неизвестные ключи — этот проект обжигался дважды).

- Бренд per-locale: en → Bitty, ru → Ночка, es → Nenita. Новые строки не должны хардкодить имя — только `brand.name`.
- CloudKit: любые новые поля моделей — optional или с дефолтом, связи optional с inverse, без `.unique`.
- Проверка после каждой задачи: `xcodebuild -project BabyBloom.xcodeproj -scheme BabyBloom -destination 'generic/platform=iOS Simulator' build` → BUILD SUCCEEDED.
- Тесты: `xcodebuild test -project BabyBloom.xcodeproj -scheme BabyBloom -destination 'platform=iOS Simulator,name=iPhone 16'`.
- Коммитить после каждой задачи, сообщения на английском: `feat:`/`fix:`/`refactor:`/`test:`/`docs:`.

## Medical Safety Constraints (обязательны, не «желательно»)

- Приложение **информирует, а не диагностирует**. Запрещены формулировки вида «недобор веса», «гипотрофия», «отставание». Разрешено: «прибавка ниже ориентира — стоит обсудить с педиатром».
- Ни один **красный флаг не прячется за пейволом**. Потеря >10% веса рождения и невосстановление к 14 дню — это безопасность, показывается всем. За Premium уходит аналитическая глубина, а не предупреждения.
- Все числовые нормы — с указанием источника в комментарии кода и с экранной сноской «ориентиры ВОЗ, не заменяют осмотр врача».
- Никаких прогнозов веса в будущее и никаких оценок «нормально/ненормально» без диапазона.

## Scope Decisions (зафиксированы с владельцем 2026-08-09)

1. Недоношенные — **в скоупе сейчас** (одна миграция вместе с весом рождения, не две).
2. Перцентиль — **бесплатно**; динамика набора (скорость, тренд коридора) — **Premium**. Исключение — красные флаги первых недель, см. Medical Safety.
3. Проактивные пуши — **делаем**.

## Phase 1 — Фундамент: данные и математика

### Task 1: Поля веса при рождении и гестационного возраста

**Files:**
- Modify: `BabyBloom/Core/Models/Baby.swift`

**Interfaces:**
- Produces: `Baby.birthWeightKg: Double?`, `Baby.gestationalWeeks: Int?`, `Baby.correctedAgeDays: Int`, `Baby.isPreterm: Bool`.

- [x] **Step 1:** Добавить в `Baby` два optional-поля: `var birthWeightKg: Double?` и `var gestationalWeeks: Int?`. Оба nil = «не указано», это валидное состояние навсегда (пользователь мог не знать). CloudKit-совместимо без миграционного кода.
- [x] **Step 2:** Computed `isPreterm: Bool { (gestationalWeeks ?? 40) < 37 }`.
- [x] **Step 3:** Computed `correctedAgeDays: Int`. Формула: `ageInDays - max(0, (40 - gestationalWeeks)) * 7`, результат не ниже 0. При `gestationalWeeks == nil` равен `ageInDays`. Коррекция применяется до 24 месяцев корректированного возраста, дальше `correctedAgeDays == ageInDays` (стандартная практика для веса).
- [x] **Step 4:** Computed `correctedAgeDescription: String?` — возвращает строку только для недоношенных, иначе nil (чтобы UI не показывал лишнего доношенным).
- [x] **Step 5:** Тесты: доношенный (gw=40) → корректированный == хронологическому; gw=32 на 100-й день → 100 - 56 = 44; gw=32 на 5-й день → 0, не отрицательное; nil → хронологический.

### Task 2: Настоящие WHO LMS вместо нормального приближения

**Files:**
- Create: `BabyBloom/Core/Growth/WHOGrowthStandard.swift`
- Modify: `BabyBloom/Core/Models/GrowthEntry.swift` (вынести `WHOPercentile`)
- Modify: `BabyBloom/Features/Growth/GrowthView.swift` (точки вызова)

**Interfaces:**
- Produces: `WHOGrowthStandard.zScore(weightKg:ageDays:isMale:) -> Double?`, `.percentile(weightKg:ageDays:isMale:) -> Double?`

Текущий `WHOPercentile` честно документирует свои упрощения: помесячная гранулярность (`ageMonths: Int`) и нормальное приближение при L≈1. Для новорождённых оба неприемлемы — разница между 3 и 25 днями жизни огромна, а приближение сильнее всего врёт в хвостах, то есть ровно там, где родителю важно.

- [x] **Step 1:** Встроить таблицы WHO Child Growth Standards, weight-for-age, LMS-коэффициенты, мальчики и девочки: понедельно 0–13 недель и помесячно 0–24 месяца. **Значения транскрибировать из публикации ВОЗ, не выводить и не выдумывать.** Источник указать в комментарии к таблице (как это уже сделано в текущем `WHOPercentile`).
- [x] **Step 2:** Интерполяция по возрасту: линейно по L, M, S между соседними узлами таблицы, ключ — возраст в днях.
- [x] **Step 3:** z-score по LMS-формуле: `z = ((value/M)^L - 1) / (L*S)` при `L != 0`, иначе `ln(value/M)/S`.
- [x] **Step 4:** Перцентиль из z через нормальный CDF (erf уже используется в текущем коде), клэмп к 1–99 для показа.
- [x] **Step 5:** Возраст вне таблицы → `nil`, а не молчаливый клэмп. Вызывающая сторона решает, что показать. Это меняет текущее поведение (сейчас 24 месяца используются для всех, кто старше) — обработать в GrowthView явным «вне диапазона».
- [x] **Step 6:** Все вызовы принимают **корректированный** возраст (`Baby.correctedAgeDays`), а не хронологический.
- [x] **Step 7:** Удалить старый `WHOPercentile` из `GrowthEntry.swift`, перенести `percentileLabel`/`percentileColor` в новый файл без изменений (границы 3/15/50/85/97 и цвета сохранить — они уже согласованы между собой).
- [x] **Step 8:** Тесты: сверить z-score с опубликованными ВОЗ контрольными точками (медиана → z=0, P3 → z≈-1.881, P97 → z≈+1.881) для обоих полов на нескольких возрастах.

### Task 3: Первые две недели — потеря и восстановление веса рождения

**Files:**
- Create: `BabyBloom/Core/Growth/NewbornWeightLoss.swift`

**Interfaces:**
- Produces: `NewbornWeightLoss.analyse(birthWeightKg:entries:birthDate:) -> NewbornWeightStatus`

Физиологическая потеря 5–10% за первые 3–5 дней с восстановлением к 10–14 дню — норма. Перцентиль в этом окне бесполезен и пугает: падение веса выглядит как провал графика.

- [x] **Step 1:** Тип `NewbornWeightStatus` с полями: `percentOfBirthWeight: Double`, `nadir: (date: Date, percent: Double)?`, `regainedOn: Date?`, `dayOfLife: Int`, `flags: [Flag]`.
- [x] **Step 2:** `Flag` — enum: `.lossExceeds10Percent`, `.notRegainedByDay14`. Только эти два, оба являются общепризнанными поводами показаться врачу. Не изобретать дополнительных порогов.
- [x] **Step 3:** Функция активна только при наличии `birthWeightKg` и возрасте до 21 дня; иначе возвращает nil — UI просто не показывает блок.
- [x] **Step 4:** Для недоношенных использовать **хронологический** возраст, не корректированный: физиологическая потеря считается от факта рождения. Это единственное место в плане, где корректированный возраст НЕ применяется — прокомментировать в коде, иначе следующий читатель «починит» на корректированный.
- [x] **Step 5:** Тесты: потеря 7% на 3-й день без флагов; 11% на 3-й день → `.lossExceeds10Percent`; вес рождения не достигнут на 15-й день → `.notRegainedByDay14`; восстановление на 9-й день → `regainedOn` заполнен, флагов нет.

### Task 4: Скорость набора, г/нед

**Files:**
- Create: `BabyBloom/Core/Growth/WeightVelocity.swift`

**Interfaces:**
- Produces: `WeightVelocity.between(_:_:) -> Double?` (г/сут, нормировано), `WeightVelocity.expectedRange(correctedAgeDays:) -> ClosedRange<Double>`, `WeightVelocity.assess(...) -> VelocityBand`

- [x] **Step 1:** Расчёт г/сут между двумя замерами с нормировкой на фактический интервал, затем перевод в г/нед для показа. Интервал <3 дней считать статистически бессмысленным и возвращать nil — суточные колебания веса младенца перекрывают недельный тренд.
- [x] **Step 2:** Референсные диапазоны по корректированному возрасту, транскрибировать из ВОЗ weight-velocity standards. Ориентировочный порядок (уточнить по источнику): 0–3 мес ~150–200 г/нед, 3–6 ~100–150, 6–12 ~70–90.
- [x] **Step 3:** `VelocityBand`: `.below`, `.within`, `.above`. Никаких оценочных названий — маппинг в текст живёт в локализации.
- [x] **Step 4:** Тесты: интервал 2 дня → nil; +180 г за 7 дней в 1 месяц → `.within`; +40 г за 7 дней в 1 месяц → `.below`.

### Task 5: Тренд по центильному коридору

**Files:**

- [x] **Step 1:** Считать перцентиль для каждого замера и искать устойчивое смещение вниз. Пороги брать из NICE faltering-growth: падение на 1 коридор при весе рождения ниже 9-го перцентиля, на 2 — при 9–91, на 3 — выше 91.

- [x] **Step 3:** Тесты: стабильный коридор → нет сигнала; снос с 50-го до 9-го за 2 месяца при нормальном весе рождения → сигнал; два замера → `.insufficientData`.

## Открытые вопросы

- ~~Референсные диапазоны скорости набора~~ — СВЕРЕНО 2026-08-09. Взяты 1-месячные таблицы приростов ВОЗ (граммы, перцентили), полосой служат P15–P85. Ориентировочные «150–200 г/нед» из первой редакции плана оказались нижним краем распределения, а не серединой: у мальчиков 0–4 недели P15 = 170 г/нед, медиана = 256, P85 = 334.
- Номограммы первых дней (NEWT, Flaherman et al.) дают раздельные кривые для естественных родов и кесарева и точнее простого правила 10%. Не включены: требуют поля «способ родоразрешения» и проверки лицензионных условий на таблицы. Кандидат на следующую итерацию.
- Fenton-кривые для глубоко недоношенных (до 40 недель постменструального возраста) не включены — используется корректированный возраст на стандартных кривых ВОЗ, что корректно для рождённых после ~32 недель и огрубляет картину для более ранних.

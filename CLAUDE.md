# CLAUDE.md — BabyBloom (Bitty / Ночка / Nenita)

iOS app for newborn tracking: feeding, sleep, diapers, growth. One repo,
three targets.

## Stack

- Swift 6.0, SwiftUI, iOS 17+, universal (iPhone + iPad)
- SwiftData for persistence, local only (no iCloud sync; DECISIONS.md has
  the way back); App Group `group.com.nenita.app` shares the store with the
  widget
- WidgetKit extension (`BabyBloomWidget`), StoreKit 2 paywall
- XCTest bundle `BabyBloomTests`

## Project generation — read this before editing anything build-related

The Xcode project is GENERATED by XcodeGen from `project.yml`. Never edit
`BabyBloom.xcodeproj` by hand — regenerate:

    xcodegen generate

XcodeGen **silently ignores unknown or misplaced keys** — no warning, no
error. After changing `project.yml`, verify the generated artifact actually
changed; do not trust that the key took. This has cost the project real time
twice (see `.team/knowledge.md`).

## Build and test

    xcodegen generate
    xcodebuild -project BabyBloom.xcodeproj -scheme BabyBloom \
      -destination 'platform=iOS Simulator,name=iPhone 17' build
    xcodebuild -project BabyBloom.xcodeproj -scheme BabyBloom \
      -destination 'platform=iOS Simulator,name=iPhone 17' test

Skills `platform-build` and `platform-test-runner` in `.claude/skills/`
carry the canonical invocations and how to report results.

## Localization

- ALL UI strings go through the JSON `LocalizationManager`
  (`BabyBloom/Resources/Localization/<lang>.json`). `NSLocalizedString`
  is never used; the `.lproj/Localizable.strings` files were deleted (PR #14).
  A key a language lacks reads English.
- `<lang>.lproj/InfoPlist.strings` IS live — it drives the per-language
  app name.
- The widget reads a **physical copy** of the JSONs in
  `WidgetResources/Localization/`. A pre-build script fails the build when
  the copies drift. To sync:
  `cp BabyBloom/Resources/Localization/$f.json WidgetResources/Localization/$f.json`
- A `SupportedLanguage` case is offered only once its JSON ships
  (`SupportedLanguage.available`). Adding a language means the case, the
  app's JSON, its widget copy and the `.lproj` folder; the pre-build script
  checks every JSON in the folder by itself. Once its file holds every key,
  add its code to `Localization/complete-languages.txt`. From then on
  `LocalizationLintTests` fails on any key missing from that language.

## Theming

The palette lives entirely in the Asset Catalog
(`BabyBloom/Resources/Assets.xcassets/Colors/`). Re-theming = colorset edits
+ the two splash PNGs + the hex constants in `ExportGenerator` and
`DoctorReportPDF` (the PDF renderer cannot read the Asset Catalog). Never hardcode a colour in a view.

## Conventions

- **Comments**: keep the project's current density (~1 comment per 6–10
  lines). Comment the *why* — non-obvious decisions, platform traps,
  ordering constraints. Never narrate what the code plainly says.
- Feature code lives under `BabyBloom/Features/<Feature>/`; shared UI under
  `DesignSystem/`; domain logic under `Core/`; side-effecting services under
  `Services/`.
- Written artifacts (code, commits, PRs, specs) in English. Conversation
  with the user in Russian.

## Knowledge base — read it, then keep it true

`ARCHITECTURE.md` is how the system works; `DECISIONS.md` is why it is that
way. Read the relevant part before changing an area — both are committed, so
unlike `.team/`, they survive a clone.

**Updating them is part of finishing a task, not a follow-up.** Before opening
a PR, ask two questions and act on the answers:

- Did this change make anything in `ARCHITECTURE.md` false, or add a mechanism
  a newcomer could not infer? → edit the affected paragraph in the same PR.
- Did this task settle something that will outlive it — an architecture
  direction, a convention, a rejected approach, a constraint invisible in the
  code? → add a dated entry to `DECISIONS.md`, **with its reason**. A decision
  without its why gets undone in a year for good-looking reasons.

Most tasks need neither. A task that needs one and skips it leaves the next
person reading a document that lies, which is worse than no document.

## Git

- Base branch `main`. One branch per task:
  `feature/<slug>` · `fix/<slug>` · `chore/<slug>`.
- Conventional commits, with the `Co-Authored-By:` trailer (matches history).
- **Who may commit is set per role in `.team/project.md` `git:`** (the Dev
  Lead, Content and Design commit on their own branches; the Manager and QA
  never do). Without `.team/` — a fresh clone, an agent outside the team —
  ask the user before every commit.
- Every task goes through a PR against `main`; never move `main` by hand.

## Workflow

Work runs through the teamdesk workflow: `.team/project.md` is the rulebook,
`.team/team.md` the roles and messages, `.team/knowledge.md` accumulated
traps, task cards in `.team/desk/tasks/`. Start a dev task with the
`team-dev-task` skill. The Maestro e2e suite lives in `maestro/` (tracked);
`.team/` itself is local and untracked.
